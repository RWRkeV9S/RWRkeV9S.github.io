QQbot重复引用同一条消息导致刷屏的解决办法

发表于2026-10-07|更新于2026-10-07
|总字数:1.1k|阅读时长:4分钟|浏览量:

不太清楚是我环境问题导致的偶然bug，还是其他人也出现过这种情况。遂写文章记录一下

表现

如图，Sylvie是bot，使用Maibot+Napcat。

体现出来的就是两条：

  • 反复回复同一条消息，甚至偶尔左右脑互博

  • planner一直在重复读取同一条消息

bug与修复方式

NapCat 发送回执误判

QQ NT 的 NodeIKernelMsgService/sendMsg 返回 {"result": 120, "errMsg": ""}。NapCat 把非 0 一律当失败（EventChecker Failed），但消息其实已经发出去了——用 OneBot WS 直接读群历史可以证实。

真正的伤害在 MaiBot 这一侧：src/maisaka/builtin_tool/reply.py 里 sent = sent_message is not None，为 False 时会 跳过 sync_to_maisaka_history=True，于是这条回复从未进入聊天历史 → planner 下一轮又把同一条消息当成「还没回过」→ 重新生成（内容不同）→ 重新发送 → 群里再收到一份。

修复方式

在适配器 handle_napcat_gateway 的 status != ok 分支里，先判断是否为 EventChecker Failed 且 "result": 120，是则返回 success=True（不带 external_message_id，MaiBot 的 _apply_successful_delivery_receipt 对空 id 会安全跳过）。

效果：MaiBot 认为发送成功 → 写入聊天历史 → planner 不会重选 → 根本不重发。

只放行 result: 120 这一个码；299（本群每分钟只能发 10 条）等真实失败仍然如实上报。

planner 回复自己

其实我觉得回复自己不太算bug，但是他一直自己回复自己刷屏+左右脑互博就不行了，不太懂怎么约束，就直接不给回复了。

MaiBot 会把机器人自己发过的消息也放进 planner 上下文，前缀标了 is_self_message="true"，但整个提示词里没有任何一处告诉 planner「不要回复自己」：

于是 planner 把「补充自己刚才的话」「保持群聊活跃」当成合理动作。它的 reply_reference 字段会把动机写得很直白：

关键实现细节：自身消息有自己独立的 msg_id，所以任何「按 (会话, 目标 msg_id) 计数」的限流都拦不住——自问自答链里每一环的目标都是新 id，计数器永远只有 1。

修复方式

patch_reply_guard2.py 往 reply.py 加三层守卫，缺一不可：

① 禁止回复自己：is_bot_self(target_message.platform, user_info.user_id) → 跳过（reason=self_target_guard）；

② 同一目标消息：窗口 1800s、上限 2 次；

③ 会话级兜底：300s 内最多 10 次 reply 调用（按调用次数计，不按消息条数，不会截断正常的 multi-segment 回复）。

超限一律返回 build_success_result，让 planner 认为动作已完成，不再重选。

deferred 工具参数错配

这是本轮的核心。循环结构如下

  1. tool_search 的返回只有工具名，没有参数表。实现见 src/maisaka/builtin_tool/tool_search.py，content_lines 只拼了 tool_name：已找到 3 个 deferred tools… / - abbreviation_translate（本次新发现）。

  2. 模型（免费档 glm-4.5-flash）拿不到参数名，只能猜。它看到工具描述里的动词「主动查询并翻译这些词汇」，于是猜成 {"query": ...}。

  3. 插件 plugins/xxxxx7258_google-search-plugin/plugin.py 声明的参数名其实是 term（ToolParameterInfo(name="term", required=True)），所以 term 恒为空。

  4. 插件返回 {"name": ..., "content": "未提供要翻译的词汇"}——框架把它记成 success: true。

  5. 框架里本来有一道提示机制 _append_deferred_tool_parameter_hint()（reasoning_engine.py:2015，会补一句「请通过 tool_search 查看具体的工具参数后再重试」），但它的第一行是 if result.success: return result —— 因为 success=True，提示永远不会触发。

  6. success=True 意味着本轮不算失败，planner 开新轮继续；参数名还是错的 → 再来一次。

  7. 没有任何刹车
